# LR EMR

## การส่งออก Excel และ CSV

หน้าทะเบียนเลือกรูปแบบแล้วกดส่งออกทุกคนทุกช่วงเวลา หรือตามวันที่ Admit (ไม่เกิน 370 วัน):

- Excel: XLSX จริง 10 ชีต รวมทะเบียนทุกช่อง ข้อมูลประกอบ ข้อมูลเสริมและประวัติแก้ไข เก็บค่าเป็นข้อความเพื่อรักษา HN/AN และเลขศูนย์นำหน้า
- CSV: ทะเบียนทุกช่องหนึ่งไฟล์ จำนวนแถวและคอลัมน์ตรงกับชีตทะเบียน Excel
- CSV ZIP: CSV ครบ 10 หมวด ไฟล์ 01.csv ถึง 10.csv ตามลำดับ: ทะเบียน, Lab ทะเบียนคลอด, ผลห้องปฏิบัติการ, วัคซีน, ภาวะแทรกซ้อน, ข้อมูลเสริม, ประวัติข้อมูลเสริม, ค่า HOSxP ก่อนแก้ไข, ข้อมูลเชื่อมโยง, รายละเอียดไฟล์
- CSV รายการที่แสดง: เฉพาะรายการที่โหลดและผ่านตัวกรองบนหน้าจอ เก็บค่าต้นฉบับรวมเวลาเต็ม ไม่ใช้รูปแบบเวลาที่แสดงบนหน้าจอ

CSV ใช้ UTF-8 BOM, comma, CRLF และ escape เครื่องหมายคำพูด รองรับข้อความหลายบรรทัด ค่าที่เสี่ยงเป็นสูตรจะเติม apostrophe เพื่อป้องกัน Excel ประมวลผลสูตร CSV ไม่มีชนิดข้อมูลของเซลล์: เมื่อนำเข้า Excel ให้ใช้ Data > From Text/CSV และตั้งคอลัมน์ HN/AN/รหัสเป็น Text เพื่อคงเลขศูนย์นำหน้า การดับเบิลคลิกเปิด CSV อาจทำให้ Excel แปลงรหัสเป็นตัวเลขเอง ค่าว่างยังเป็นค่าว่างและเลข 0 ยังคงเป็น 0

ทุกการส่งออกจากเซิร์ฟเวอร์ต้องผ่าน session/MFA, POST และ CSRF พร้อมบันทึกประวัติ หากฐานเสริมอ่านไม่ได้จะไม่ส่งออกไฟล์ที่ขาดข้อมูล ไฟล์ชั่วคราวถูกลบหลังดาวน์โหลด

## MFA และรายงานรายบุคคล / Excel

ตั้งแต่รุ่นนี้ทุกบัญชีต้องยืนยัน MFA หลังผ่านรหัสผ่าน HOSxP รวมถึงบัญชีใน app_allowed_users ระบบจะให้ลงทะเบียน Authenticator ในการเข้าสู่ระบบครั้งแรก สแกน QR Code ที่แสดงในหน้าตั้งค่า หรือป้อนคีย์ในแอปแบบตามเวลา (TOTP SHA-1, 6 หลัก, 30 วินาที ตาม RFC 6238) แล้วยืนยันรหัสจากโทรศัพท์ เก็บรหัสกู้คืน 10 ชุดที่แสดงเพียงครั้งเดียวแยกจากรหัสผ่าน แต่ละชุดใช้ได้ครั้งเดียว ไม่มีการส่งคีย์หรือรหัสไปยังบริการภายนอก ไม่มีการเปลี่ยนวิธีตรวจรหัสผ่าน HOSxP เดิม

ขั้นตอน MFA มีอายุ 5 นาที จำกัดการลองทั้งบัญชีและ IP ปฏิเสธ TOTP ที่ใช้แล้ว และตรวจสิทธิ์บัญชีก่อนให้ session เต็ม Session ที่สร้างก่อนติดตั้ง MFA ต้องเข้าสู่ระบบใหม่ ห้ามให้ผู้อื่นลงทะเบียน MFA แทนเจ้าของบัญชีในการเปิดใช้ครั้งแรก

ต้องมี PHP extension openssl และให้ผู้รัน PHP เขียน .private ได้ คีย์ TOTP และค่า hash รหัสกู้คืนเก็บใน .private/mfa/accounts.php ที่เข้ารหัส AES-256-GCM ด้วย .private/mfa/key.php ห้ามเผยแพร่ .private และจำกัดสิทธิ์ระบบไฟล์ให้เฉพาะผู้ดูแล/ผู้รัน PHP สำรองไฟล์ accounts.php พร้อม key.php อย่างปลอดภัย การสูญเสีย key.php ทำให้ถอดรหัส MFA ทั้งหมดไม่ได้ อย่าลบหรือสร้างไฟล์ MFA ทับระหว่างอัปเดต ระบบล็อกไฟล์และเขียนแบบแทนที่เพื่อป้องกันการใช้รหัสซ้ำพร้อมกัน

กรณีโทรศัพท์หายให้ใช้รหัสกู้คืนเข้าสู่ระบบ หากไม่มีรหัสเหลือ ผู้ดูแลเซิร์ฟเวอร์ต้องยืนยันตัวเจ้าของบัญชีก่อนรันจาก CLI:

    php tools/reset-mfa.php --user=USERNAME --confirm=USERNAME

คำสั่งนี้เพิกถอน MFA และ session เดิมทั้งหมดของบัญชีนั้น จากนั้นเจ้าของบัญชีเข้าสู่ระบบด้วยรหัสผ่าน HOSxP เพื่อลงทะเบียนใหม่ ไม่มีหน้าเว็บให้ปิด MFA หรือข้าม MFA

ในเมนูเวชระเบียน เลือกผู้ป่วยแล้วกด “พิมพ์รายบุคคลทุกหมวด” ระบบอ่านข้อมูลที่บันทึกแล้วใหม่จากเซิร์ฟเวอร์ ครอบคลุม AN ที่เลือกและทารกทุกคนของ AN นั้น รวมทุกช่องที่ซ่อนในหน้าจอ ผล Lab วัคซีน และภาวะแทรกซ้อน จัดหน้ากระดาษ A4 พร้อมช่องผู้ตรวจสอบ เลือกพิมพ์หรือบันทึก PDF ในเบราว์เซอร์ ต้องบันทึกข้อมูลที่กำลังแก้ไขก่อนพิมพ์

ในเมนูทะเบียนมีปุ่ม “Excel ทุกคน · ทุกช่วงเวลา” และ “Excel ตามช่วงวันที่” ไฟล์ .xlsx เป็น Excel จริง รวมผู้รับบริการประเภทคลอดบุตรในขอบเขตเดียวกับทะเบียน LR EMR หนึ่งแถวต่อระเบียนมารดา/ทารก ไม่จำกัดตามคำค้น กลุ่มที่กรอง หรือเพดาน 200/10,000 แถวของหน้าจอ มี 10 ชีต: ทะเบียนมารดาและทารก, Lab ทะเบียนคลอด, ผลห้องปฏิบัติการ, วัคซีน, ภาวะแทรกซ้อน, ข้อมูลเสริม, ประวัติข้อมูลเสริม, ค่า HOSxP ก่อนแก้ไข, ข้อมูลเชื่อมโยง และรายละเอียดไฟล์

“ทุกช่อง” หมายถึงทุกช่องในโครงสร้างรายงาน LR EMR รวมช่องที่ซ่อนและรายการประกอบ ไม่ใช่ทุกตารางในฐาน HOSxP เก็บค่าใน Excel เป็นข้อความเพื่อรักษาศูนย์นำหน้า HN/AN และป้องกันการตีความข้อมูลเป็นสูตร ค่าว่างคงเป็นค่าว่าง ไม่สร้างข้อมูลทดแทน หากฐานเสริมไม่พร้อมจะไม่ส่งออกไฟล์ที่ข้อมูลไม่ครบ หากข้อมูลเกินขีดจำกัด Excel จะหยุดและแจ้งให้ลดช่วงวันที่ การส่งออกจำนวนมากใช้เวลาและหน่วยความจำของ PHP ตามปริมาณข้อมูล รายงานขนาดใหญ่ขอ memory_limit อย่างน้อย 512 MB และเวลาทำงาน 180 วินาที หากเซิร์ฟเวอร์จำกัดไว้เข้มกว่าให้ผู้ดูแลปรับ PHP-FPM ตามทรัพยากร ข้อมูลย้อนหลังที่มีไบต์ TIS-620 ผิดรูปแบบจะแสดงเป็น \xNN พร้อมเก็บค่า hex เดิมในชีตข้อมูลเชื่อมโยง/หมายเหตุการเข้ารหัส ไม่ตัดข้อมูลแถวนั้นทิ้ง ไฟล์ชั่วคราวอยู่ใน .private/exports และลบทันทีหลังส่งไฟล์

บันทึกประวัติการตั้งค่า/ยืนยัน MFA การจัดทำแบบพิมพ์ และการส่งออก Excel โดยไม่บันทึก OTP คีย์ หรือรหัสกู้คืน สำหรับ Apache ต้องอัปเดตทั้ง .htaccess และ deploy/apache-lr-emr.conf เพื่ออนุญาต endpoint mfa.php และอัปโหลด mfa.php, mfa-store.php, export-report.php พร้อมไฟล์ระบบที่เปลี่ยนแปลง

ทดสอบอัตโนมัติบนเครื่องพัฒนา: tools/verify-mfa-export.php ตรวจ RFC vectors และไฟล์ตัวอย่าง, tools/verify-mfa-flow.cjs ตรวจขั้นตอน MFA ด้วยบัญชีจำลองแยกจากข้อมูลจริง, tools/verify-report-api.cjs ตรวจ SQL/API แบบอ่านอย่างเดียวและจำนวนแถวส่งออก โดยไม่บันทึกค่าผู้ป่วยเป็นไฟล์ทดสอบ

อัปเดตแหล่งข้อมูล ANC 14/11/2569: GA เมื่อคลอดอ่านจาก ipt_pregnancy.ga/ga_day แยกจาก GA ฝากครั้งแรกใน ipt_labour.ga/ga_day; TP อ่าน ipt_labour.t และ Pre อ่าน ipt_labour.p; ชื่อสามีใช้ labor.hname ของ AN เดียวกันก่อนทะเบียน person_anc และสถานที่ ANC ใช้ ipt_pregnancy.anc_place_name เมื่อช่องใน ipt_labour ว่าง ค่า NULL ของ Pre/A/L และวันของ GA ครั้งแรกแสดง 0 ตามหน้าจอ HOSxP พร้อมข้อความกำกับ โดย API/CSV ยังคง NULL และไม่สร้างข้อมูลเสริมจนกว่าผู้ใช้จะแก้ไขจริง อัปเดต index.php, report.php และ report-fields.php พร้อมกัน บัญชี HOSxP ต้องอ่าน ipt_pregnancy ได้ ตรวจด้วย tools/check-server.php

ระบบเวชระเบียนห้องคลอด PHP 8.4 เชื่อม HOSxP แบบอ่านอย่างเดียว และเก็บข้อมูลเพิ่มเติมใน MySQL/MariaDB ฐาน lr_supplement แยกต่างหาก

## ไฟล์ที่ใช้งาน

- index.php: หน้าจอ EMR, Dashboard, ทะเบียน, Lab และคัดกรองทารกเสี่ยง
- login.php / logout.php / security.php / auth-bootstrap.php / hosxp-auth.php / login-throttle.php: เข้าสู่ระบบและ Session
- api.php / report.php / report-fields.php / report-labs.php / providers.php: อ่านข้อมูล HOSxP และรายชื่อผู้ทำคลอด Active
- risk.php / infant-risk.php: คัดกรองตามเกณฑ์ APGAR และน้ำหนัก
- manual.php / manual-store.php: ตรวจสอบและบันทึกข้อมูลเพิ่มเติมพร้อม audit/version
- field-options.php + database/sheet-options-source.json: ตัวเลือกจากชีตสำเนาที่ผู้ใช้ระบุ
- config.php: การเชื่อมต่อ HOSxP และบัญชีที่อนุญาตเพิ่มเติม
- supplement.config.php: การเชื่อมต่อฐานเสริมที่ใช้อยู่บนเครื่องนี้
- database/supplement.sql / grants-example.sql: schema และตัวอย่างสิทธิ์ของฐานเสริม
- deploy/: คู่มือ AlmaLinux 9 และ Apache/SELinux สำหรับ /var/www/html/LR_HOSxP_Live
- tools/check-server.php: ตรวจ PHP, การเชื่อมต่อและสิทธิ์อ่านตาราง
- tools/setup-supplement.php: ติดตั้ง schema/ย้ายข้อมูล legacy ด้วยบัญชีติดตั้งที่ได้รับอนุญาต
- tools/start-local.ps1: เปิด PHP 8.4 และ MySQL ทดสอบบน Windows
- tools/build-release.ps1: สร้างชุดติดตั้งจากรายชื่อไฟล์ที่อนุญาต โดยไม่ใส่ค่าลับหรือข้อมูลจริง

## เปิดบนเครื่องพัฒนา

    powershell -ExecutionPolicy Bypass -File tools/start-local.ps1

เว็บ: http://127.0.0.1:8089/index.php
ฐานเสริมสำหรับเครื่องพัฒนา: ดู supplement.config.php (ไม่ได้เปลี่ยนเป็นฐานปลายทางอัตโนมัติ)
ตรวจความพร้อม: php tools/check-server.php

## นำขึ้นเซิร์ฟเวอร์

อ่าน deploy/README-server.md ก่อนติดตั้ง ตั้งค่าจริงจาก config.example.php และ supplement.config.example.php ไม่ใช้ PHP built-in server ใน production ใช้ HTTPS ที่เชื่อถือได้

ไฟล์ตั้งค่าสำหรับเซิร์ฟเวอร์ที่เตรียมไว้แยกอยู่ใน .private/server-configs/ ให้นำ config.php และ supplement.config.php จากโฟลเดอร์นี้ไปวางที่ root ของเว็บบนเซิร์ฟเวอร์เท่านั้น ห้ามอัปโหลดไฟล์ผู้ดูแล MySQL ของเครื่องพัฒนา

## ข้อมูลและการเข้าใช้

- บัญชี HOSxP ตรวจด้วย opduser.passweb และสิทธิ์กลุ่มพยาบาล/บัญชี app_allowed_users ตามที่กำหนด ไม่เก็บรหัสผ่านใน Session
- Session idle 30 นาที อายุรวม 8 ชั่วโมง ตรวจสิทธิ์ซ้ำทุก 60 วินาที Logout ใช้ POST+CSRF และจำกัดการลองรหัสซ้ำ
- ช่องว่างกรอกเพิ่มเติมได้ ข้อมูล HOSxP มีลำดับความสำคัญก่อน ยกเว้น G/TP/Pre/A/L และคู่ชื่อ/รหัสผู้ทำคลอดที่อนุญาตให้ override
- ผู้ทำคลอดต้องเป็นแพทย์หรือพยาบาล Active=Y ตรวจซ้ำตอนบันทึก ชื่อมาจากรหัสที่เลือกจริง
- รายชื่อห้องคลอดปัจจุบันใช้ ward=04 และยังไม่จำหน่าย ไม่จำกัดวัน Admit ส่วนประวัติใช้ช่วงวัน Admit
- คัดกรองทารกเสี่ยงใช้วันเกิด แยกแหล่ง ipt_labour_infant/ipt_newborn ไม่รวมยอดซ้ำ เกณฑ์ตามคำสั่งผู้ใช้และไม่แทนการวินิจฉัย
- ข้อมูล Lab ผูกกับ AN หรือ VN ตอน Admit ของมารดา ไม่ดึงทุกประวัติ HN และไม่รวมผลทารกโดยอัตโนมัติ

## โฟลเดอร์ .private

เก็บข้อมูล runtime ที่ไม่ควรเปิดผ่านเว็บ ได้แก่ login-attempts.php และ logs/ ส่วน local-db-admin.php เป็นบัญชีดูแล MySQL ทดสอบที่ยังจำเป็นสำหรับดูแลข้อมูลบนเครื่องนี้ ไม่ใช่บัญชีแอป production

supplement-server.config.php และ server-configs/ เป็นค่าปลายทางที่เตรียมไว้ ไม่แสดงรหัสผ่านในคู่มือ อย่า commit หรือเผยแพร่โฟลเดอร์นี้

## การล้างไฟล์

ลบหน้าทดสอบ/ภาพทดสอบ ชุดติดตั้งเก่า tests/ ไฟล์ .bak log เก่าที่ root และ SQL สำเนาที่ระบบไม่ได้เรียกใช้แล้ว สำรองรายการเหล่านี้นอก web root ก่อนลบ พร้อมตรวจ SHA256 เทียบครบทุกไฟล์ ไม่ลบฐานข้อมูล ข้อมูลเสริม หรือค่าการเชื่อมต่อที่ใช้งาน

## ประวัติการใช้งาน

รุ่นนี้เพิ่ม usage-log.php, usage.php และ usage-history.php บันทึก login สำเร็จ/ไม่สำเร็จ, logout, session หมดอายุ, โหลด/ค้นหาข้อมูล, เปิดเวชระเบียน, เริ่มส่งออก CSV และบันทึกข้อมูลเพิ่มเติม โดยเก็บเวลาไทย ผู้ใช้ IP และ metadata ที่จำเป็น ไม่เก็บรหัสผ่านหรือข้อความค้นหา

เก็บแยกรายวันใน .private/usage-YYYY-MM-DD.php โดยล็อกไฟล์ขณะอ่าน/เขียน ไม่ต้องเพิ่มตารางฐานข้อมูล ประวัติเริ่มหลังติดตั้ง ไม่มีข้อมูลย้อนหลัง ควรสำรองและกำหนดอายุเก็บตามนโยบายหน่วยงาน ลบไฟล์ประวัติการใช้งานที่เกิน 60 วันรวมวันนี้อัตโนมัติเมื่อบันทึกหรือเปิดประวัติ ไม่มีหลักประกันป้องกันผู้ดูแลเซิร์ฟเวอร์แก้ไฟล์

เมนู “ประวัติการใช้งาน” แสดงเฉพาะประวัติของผู้ใช้ที่เข้าสู่ระบบ เลือกวันและแสดงล่าสุดไม่เกิน 500 รายการต่อวัน หากต้องการให้ผู้ดูแลดูทั้งหมด เพิ่มคีย์นี้ใน array ของ config.php โดยใช้บัญชีที่ได้รับมอบหมายจริง:

    'audit_view_users' => ['ชื่อผู้ใช้ผู้ดูแล'],

ไม่เพิ่มบัญชีใดเป็นผู้ดูแลอัตโนมัติ .private ต้องเขียนได้โดย PHP-FPM และห้ามเปิดผ่านเว็บ หาก VirtualHost มี FilesMatch จำกัด endpoint ให้เพิ่ม usage และ usage-history ในรายชื่อไฟล์ที่อนุญาตทั้งส่วน Require และ SetHandler ตาม deploy/apache-lr-emr.conf รุ่นนี้ การอัปโหลด .htaccess อย่างเดียวไม่แทนที่ข้อจำกัดระดับ VirtualHost

กิจกรรมเปิดเวชระเบียนและเริ่มส่งออกเป็นข้อมูลจาก browser ไม่รับประกันว่าผู้ใช้เห็นหน้าหรือบันทึกไฟล์สำเร็จ การส่งออกจะหยุดหากบันทึกประวัติไม่ได้ ส่วนงานอื่นยังทำต่อและแจ้งข้อผิดพลาดลง PHP error log เมื่อเขียนไม่ได้ ประวัติแก้ข้อมูลรายช่องก่อน/หลังยังอยู่ใน supplement_audit เดิม

อัปเดตไฟล์: usage-log.php, usage.php, usage-history.php, auth-bootstrap.php, security.php, login.php, logout.php, api.php, manual.php, index.php และ .htaccess โดยคง config.php, supplement.config.php และ .private ของเซิร์ฟเวอร์เดิมไว้

Dashboard: การ์ดทารกแรกเกิดแผนกกุมารนับ AN ไม่ซ้ำจาก ipt โดยแผนกกุมารเวชกรรมและประเภทรับไว้แรกเกิด ใช้ช่วงวัน Admit ทารก ไม่ต้องมีทะเบียนคลอดมารดา ส่วนมารดา น้ำหนัก/APGAR และกราฟยังอิงทะเบียนคลอดตามเกณฑ์เดิม อัปเดต api.php, report.php และ index.php พร้อมกัน

ความสัมพันธ์แม่–ลูก: family.php อ่านคู่ AN จาก ipt_newborn.mother_an/an และ ipt_labour.an/ipt_labour_infant.infant_an แสดง AN ลูกทั้งหมดในข้อมูลแม่และ AN แม่ในรายการทารก (กดการ์ดทารกแรกเกิดแผนกกุมาร) รองรับลูกหลายคน หาก AN ลูกเชื่อมแม่หลาย AN จะแจ้งข้อมูลขัดแย้งและไม่ยืนยันคู่ ไม่เขียนกลับ HOSxP อัปเดต family.php, api.php และ index.php พร้อมกัน
